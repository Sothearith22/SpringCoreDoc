🏷️ Stereotype Annotations

Annotation Purpose Usage
@Component Generic stereotype for any Spring-managed bean Core
@Service Marks service layer beans containing business logic Service Layer
@Repository Marks DAO/repository beans; adds automatic exception translation Data Layer
@Controller Marks Spring MVC controller beans Web Layer
@RestController Combines @Controller and @ResponseBody for REST APIs REST API
@Configuration Defines configuration classes with @Bean methods Configuration

💉 Injection Annotations

Annotation Purpose Usage
@Autowired Injects dependencies automatically by type; optional with single constructor Injection
@Qualifier Specifies which bean to inject when multiple beans of same type exist Injection
@Primary Marks a bean as the default choice when multiple beans exist Injection
@Value Injects property values from application.properties or application.yml Configuration
@Resource JSR-250 annotation; injects by name (not Spring-specific) Injection
@Inject JSR-330 annotation; similar to @Autowired (not Spring-specific) Injection

🔧 Bean Definition & Lifecycle Annotations

Annotation Purpose Usage
@Bean Explicitly declares a Spring bean in @Configuration class Configuration
@Scope Defines bean scope: singleton, prototype, request, session, etc. Lifecycle
@Lazy Delays bean initialization until first request Lifecycle
@PostConstruct Marks method to execute after dependency injection is complete Lifecycle
@PreDestroy Marks method to execute before bean is destroyed Lifecycle
@DependsOn Forces specific beans to be initialized before this bean Lifecycle
@Profile Activates bean only when specific profile(s) are active Configuration
@Conditional Creates bean only when specific conditions are met Conditional

🌐 Bean Scopes (@Scope Values)

Scope Description
singleton Default scope. Single instance per Spring IoC container
prototype New instance each time the bean is requested
request Single instance per HTTP request (WebApplicationContext only)
session Single instance per HTTP session (WebApplicationContext only)
application Single instance per ServletContext lifecycle
websocket Single instance per WebSocket lifecycle

✅ Best Practices for Spring DI

  • Prefer Constructor Injection for mandatory dependencies
  • Use Setter Injection only for optional dependencies
  • Avoid Field Injection in production code
  • Mark dependencies as final when using constructor injection
  • Use @Qualifier or @Primary to resolve bean conflicts
  • Keep beans stateless for singleton scope
  • Use interfaces for better abstraction and testing
